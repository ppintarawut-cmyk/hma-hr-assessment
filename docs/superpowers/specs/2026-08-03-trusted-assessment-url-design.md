# Trusted Assessment URL — Design

วันที่: 2026-08-03

ไฟล์ที่แตะ:

- repo ใหม่ `assessment` — `index.html` (แก้), `privacy.html` (ใหม่), `CNAME` (ใหม่)
- repo เดิม `hma-hr-assessment` — `index.html` (แทนด้วยหน้า redirect),
  `hma-testing-system.html` (ลบ), template อีเมล (ใหม่), สคริปต์ migration (ใหม่)
- ไม่แตะ `hma-ats.html` เลย

## ปัญหา

ผู้สมัครไม่กล้ากดลิงก์แบบทดสอบ และถามกลับมาว่าเป็นของจริงหรือเปล่า

สาเหตุคือระบบ **พิสูจน์ตัวเองไม่ได้** — ผู้สมัครได้ URL
`https://ppintarawut-cmyk.github.io/hma-hr-assessment/` ซึ่งเป็นชื่อบุคคล แล้วถูกขอ
ชื่อ-นามสกุล เลขบัตรประชาชน อีเมล เบอร์โทร โดยหน้าเว็บไม่บอกว่าใครรับผิดชอบและติดต่อใครได้
หน้าตาแบบนี้แยกไม่ออกจากหน้า phishing

ตรวจโค้ดเพิ่มแล้วพบปัญหาที่เกี่ยวเนื่องกันสี่ข้อ:

1. **เก็บเลขบัตรประชาชนโดยไม่มีวัตถุประสงค์** — HR ยืนยันว่าไม่ได้ใช้เลย เก็บมาตามฟอร์มเดิม
   และเลขถูก push ขึ้น Firestore เต็ม 13 หลัก (`cloudPushOnComplete()`, `index.html:5524`)
   ขัดหลัก data minimization ของ PDPA ตรง ๆ
2. **ข้อความ consent อ้างเอกสารที่ไม่มีอยู่จริง** — `pdpa_info` (`index.html:1390`) บอกว่า
   "เก็บรักษาภายใต้นโยบายความเป็นส่วนตัว (PDPA)" แต่ไม่มีหน้านโยบายและไม่มีลิงก์
3. **ข้อความ consent ไม่ตรงกับข้อมูลที่เก็บจริง** — `pdpa_consent` (`index.html:1391`)
   ระบุ ชื่อ-นามสกุล / เลขประจำตัวประชาชน / อีเมล / ผลการทดสอบ แต่ฟอร์มเก็บ
   **เบอร์โทรศัพท์** (`index.html:747`) และ **อายุ / ประสบการณ์ / ตำแหน่งที่สมัคร** ด้วย
   โดยไม่ได้ประกาศ
4. **เครื่องมือภายในถูกเสิร์ฟสาธารณะ** — `hma-ats.html`, `CONTEXT.md`, `README.md`,
   `hma-personality.html` และ `hma-testing-system.html` (สำเนาซ้ำของ `index.html`)
   ทั้งหมดตอบ HTTP 200 บน Pages ไม่ใช่ข้อมูลรั่ว (ATS เป็น local-first ตาม decision 0001
   และการอ่าน cloud ต้องผ่าน Firebase Auth + `admin_roles`) แต่เปิดเผยเกณฑ์ให้คะแนน
   และ logic การคัดคนโดยไม่มีเหตุผลต้องเปิด

## ขอบเขต

**ทำ**

- ย้ายหน้าผู้สมัครไป repo ใหม่ที่มีเฉพาะไฟล์ที่ต้อง public แล้วผูก
  `assessment.hinomotorsasia.com`
- แผงยืนยันตัวตนบนหน้าแรก ก่อนผู้สมัครกรอกข้อมูลใด ๆ
- หน้า `privacy.html` ฉบับจริงที่ consent ลิงก์ไปถึง
- เลิกเก็บเลขบัตรประชาชน เปลี่ยน key ภายในเป็นอีเมล และล้างเลขเก่าออกจาก Firestore
- แก้ข้อความ consent ให้ตรงกับข้อมูลที่เก็บจริงทุกรายการ
- Template อีเมลเชิญสอบที่บอก URL ล่วงหน้า
- หน้า redirect ที่ repo เดิม เพื่อไม่ให้ลิงก์ที่ส่งไปแล้วตาย

**ไม่ทำ (ตั้งใจตัดออก รอบนี้)**

- ไม่ย้าย scoring/เฉลยไปฝั่ง server — เป็นเรื่อง *ความน่าเชื่อถือของผลสอบ* คนละเรื่องกับ
  *ความปลอดภัยของข้อมูลผู้สมัคร* และใหญ่พอที่จะเป็น spec ของตัวเอง
- ไม่ย้าย Firebase project ออกจากบัญชี Gmail ส่วนตัว — ต้องมีบัญชีบริษัทก่อน
- ไม่ย้าย/ปิด ATS — Pin เลือกคงไว้ที่เดิมและแก้ในเฟส 2 ดีไซน์นี้จึงออกแบบให้ ATS
  **ไม่ถูกรบกวนและไม่แตะ domain บริษัทเลย**
- ไม่แก้ Firestore rules ที่ยอมให้ create `exam_records` แบบไม่ต้อง login
- ไม่ทำชุดเอกสารขออนุมัติเต็มรูปแบบ — เฟส 2

## การตัดสินใจที่ยืนยันแล้ว

1. **สถานะระบบ** — ทีมรู้กันแต่ยังไม่มีการอนุมัติเป็นทางการ ดังนั้น**ห้ามเคลมแบรนด์เกินจริง**
   ไม่สร้าง GitHub org ชื่อ `hino-*` และไม่ทำอะไรที่ทำให้ดูเหมือนได้รับอนุมัติแล้ว
   ทางที่ถูกคือทำให้ **ตรวจสอบกลับไปหาคนจริงได้** ไม่ใช่ทำให้ดูใหญ่
2. **Domain** — `assessment.hinomotorsasia.com` โดยขอ CNAME record จาก IT
   ไม่เอา `*.github.io` และไม่ซื้อ domain ส่วนตัว
3. **แยก repo** — สร้าง repo ใหม่สำหรับหน้าผู้สมัครเท่านั้น ไม่ใช้ folder `/docs`
   (เพราะ `docs/` เก็บ spec ภายในอยู่แล้ว จะกลายเป็น public ทันที) และไม่ตั้ง
   gh-pages + Actions เพราะไม่จำเป็น
4. **เลขบัตรประชาชน** — เลิกเก็บ ไม่ใช่ hash ไว้ เพราะเลข 13 หลักมี entropy ต่ำ
   และ salt ต้องอยู่ใน JS ฝั่ง client ซึ่งเปิดอ่านได้ การ hash จึง brute-force ย้อนกลับได้
   ในไม่กี่วินาที = ให้ความสบายใจปลอม ๆ
5. **key ใหม่คืออีเมลตัวพิมพ์เล็ก** — เพราะ ATS จับคู่ผลสอบด้วยอีเมลอยู่แล้ว
   (`hma-ats.html:1135`) เปลี่ยนแล้วสองระบบใช้ identity เดียวกัน แทนที่จะมีสองอันเหมือนตอนนี้

## ข้อจำกัดที่ยึด

- ไฟล์เดียว ไม่มี build step ไม่มี dependency (เหมือนทุก feature ที่ผ่านมา)
- ATS ต้องทำงานเหมือนเดิมทุกอย่าง URL เดิม localStorage เดิม ไม่ต้อง migrate
- ลิงก์เก่าที่ส่งผู้สมัครไปแล้วต้องยังใช้ได้
- GitHub Pages ฟรีรองรับเฉพาะ repo public — repo ใหม่จึงต้อง public และต้องมีเฉพาะ
  ไฟล์ที่ตั้งใจให้เปิดเผย

## สถาปัตยกรรม

แยก "หน้าบ้าน" (ผู้สมัคร) ออกจาก "หลังบ้าน" (HR) ที่ระดับ repo

```
repo ใหม่: assessment (public)         repo เดิม: hma-hr-assessment (คงไว้)
  index.html      ← หน้าสอบ              hma-ats.html     ← HR ใช้ต่อ URL เดิม
  privacy.html    ← ใหม่                 index.html       → หน้า redirect
  hino-logo.png                         hma-personality.html
  CNAME           ← ใหม่                 docs/ tests/ CONTEXT.md
  .nojekyll
        ↓
  assessment.hinomotorsasia.com
```

`hma-testing-system.html` เป็นสำเนาซ้ำของ `index.html` — ไม่ยกไป repo ใหม่ และลบทิ้งจาก
repo เดิมด้วย เพราะเป็น URL สาธารณะที่ซ้ำซ้อนและเคยเป็นต้นเหตุของ incident รอบก่อน
(ไฟล์ `.js` ที่ตายแล้วแต่ยังรั่วรหัสผ่านผ่าน Pages)

**ผลพลอยได้จากการแยก repo:** ATS ไม่ต้อง migrate localStorage เลยเพราะ origin ไม่เปลี่ยน
และ ATS ไม่มีวันไปโผล่บน `assessment.hinomotorsasia.com`

## ชิ้นงาน

### 1. repo `assessment` + custom domain

- สร้าง repo public ชื่อ `assessment` มีเฉพาะ `index.html` `privacy.html` `hino-logo.png`
  `.nojekyll` `CNAME`
- `CNAME` มีบรรทัดเดียว: `assessment.hinomotorsasia.com`
- เปิด GitHub Pages จาก branch `main` root แล้วเปิด **Enforce HTTPS**
- IT เพิ่ม DNS record: `assessment` CNAME → `ppintarawut-cmyk.github.io`

**ลำดับที่ต้องระวัง:** commit `CNAME` เข้า repo *ก่อน* ตั้งค่าใน Settings แล้วรอ DNS
propagate ก่อนเปิด Enforce HTTPS ไม่งั้น GitHub จะออกใบรับรองไม่สำเร็จและติดสถานะค้าง

### 2. แผงยืนยันตัวตน

วางบนหน้าแรก **เหนือฟอร์ม** มองเห็นได้ก่อนกรอกข้อมูลใด ๆ ไม่ต้องกดเปิด ต้องมี:

- ชื่อบริษัทเต็ม: Hino Motors Asia (HMA)
- วัตถุประสงค์: แบบทดสอบประกอบการพิจารณาใบสมัครงาน
- **ชื่อ + อีเมล + เบอร์โทรของ HR ผู้รับผิดชอบ** — อีเมลต้องเป็น `@hinomotorsasia.com`
- ลิงก์ไป `privacy.html`
- ระยะเวลาเก็บข้อมูล: 2 ปี (decision 0004)
- ประโยคเชิญให้ตรวจสอบ: ถ้าไม่แน่ใจว่าลิงก์นี้ของจริง ให้โทรหาเบอร์ข้างต้น

หัวใจคือ **ผู้สมัครต้องติดต่อคนจริงเพื่อยืนยันได้** ไม่ใช่แค่หน้าเว็บดูดีขึ้น

### 3. `privacy.html`

หน้าเดี่ยว สไตล์เดียวกับ `index.html` ไม่มี dependency เนื้อหา:

- ผู้ควบคุมข้อมูล: HMA และช่องทางติดต่อ
- **รายการข้อมูลที่เก็บจริงทุกรายการ**: ชื่อ-นามสกุล · อีเมล · เบอร์โทรศัพท์ · อายุ ·
  ประสบการณ์ (ปี) · ตำแหน่งที่สมัคร · คำตอบและผลการทดสอบ
- วัตถุประสงค์ · ฐานทางกฎหมาย (ความยินยอม)
- ที่เก็บ: Google Firestore และเครื่องของผู้ใช้
- ระยะเวลาเก็บ 2 ปี
- สิทธิของเจ้าของข้อมูลตาม PDPA และวิธีใช้สิทธิ (อีเมลถึง HR ผู้รับผิดชอบ)
- วันที่ปรับปรุงล่าสุด

### 4. เลิกเก็บเลขบัตรประชาชน

| จุด | ตำแหน่ง | ทำอะไร |
|---|---|---|
| ช่องกรอกเลขบัตร | `index.html:705` | ลบทั้ง field |
| validation 13 หลัก | `index.html:1755` | ลบ และถอด `e-nid` ออกจาก `clearErrs()` (`index.html:1732`) |
| ข้อความ consent | `index.html:1391` | ตัด "เลขประจำตัวประชาชน" ออก และเพิ่มรายการที่เก็บจริงให้ครบตามข้อ 3 |
| ข้อความ `pdpa_info` | `index.html:1390` | เพิ่มลิงก์ไป `privacy.html` |
| คอลัมน์แสดงเลขบัตร | `index.html:2630` | เปลี่ยนเป็นอีเมล |
| key ทั้งหมด (~91 จุด) | ทั่วไฟล์ | `applicant.nid` → `applicant.key` |

ชื่อ field ใน record หลังเปลี่ยน — ทั้งสอง collection ใช้ชื่อเดียวกันคือ `candidate_key`:

| collection | field เดิม | field ใหม่ |
|---|---|---|
| `exam_records` | `national_id` | `candidate_key` |
| `result_snapshots` | `nid` | `candidate_key` |

ต้องแก้ทั้งข้อความ `th` และ `en` ในตาราง i18n

**Read-compat หนึ่งบรรทัดที่ทุกจุดอ่านต้องใช้ร่วมกัน:**

```js
// r.national_id = exam_records เดิม, r.nid = result_snapshots เดิม
const key = r.candidate_key || (r.email || '').toLowerCase() || r.national_id || r.nid || '';
```

**เพิ่มขั้นยืนยันอีเมล** ก่อนเริ่มสอบ: แสดงอีเมลที่กรอกด้วยตัวอักษรขนาดใหญ่ให้ผู้สมัคร
กดยืนยัน เพราะอีเมลกลายเป็น key แล้ว การพิมพ์ผิดจะทำให้ผลสอบจับคู่กับใบสมัครไม่ได้

### 5. Template อีเมลเชิญสอบ

ไฟล์ markdown ใน repo เดิม (ไม่ใช่ repo public) ให้ HR คัดลอกไปใช้ ต้องมี:

- ส่งจาก `@hinomotorsasia.com`
- **บอก URL เต็มเป็นข้อความ** ให้ผู้สมัครเทียบกับ address bar ได้
- ชื่อผู้ส่งจริงและเบอร์ติดต่อ ซ้ำกับที่แสดงบนหน้าเว็บ
- บอกว่าจะไม่มีการขอรหัสผ่านหรือข้อมูลการเงินใด ๆ

### 6. หน้า redirect ที่ repo เดิม

แทนที่ `index.html` เดิมด้วยหน้า redirect ไป `https://assessment.hinomotorsasia.com/`
พร้อมข้อความบอกว่าย้ายแล้ว เผื่อ redirect ไม่ทำงาน — ทำให้ลิงก์ที่ส่งไปแล้วไม่ตาย

## Migration ข้อมูลเก่า

| ที่เก็บ | ทำอะไร | ใครทำ |
|---|---|---|
| Firestore `exam_records` | เขียน `candidate_key` จาก `email` แล้วลบ field `national_id` | สคริปต์ + Pin (ต้องสิทธิ์ superadmin) |
| Firestore `result_snapshots` | เหมือนกัน (field ชื่อ `nid`) | เหมือนกัน |
| localStorage เครื่อง HR | อ่านแบบ fallback แล้วเขียนกลับ | อัตโนมัติเมื่อเปิดหน้า |

**ก่อน migrate ต้องนับ record ที่ไม่มี `email` ก่อน** ถ้ามี ให้หยุดและรายงาน Pin แยก
ห้ามลบ `national_id` ของกลุ่มนั้นจนกว่าจะตัดสินใจ เพราะจะเหลือ record ที่ไม่มี key เลย

**export สำรอง Firestore ก่อนลบเสมอ** — การลบ field กู้ไม่ได้ (แต่ในแง่ PDPA การลบนี่คือ
สิ่งที่ถูก: ข้อมูลที่ไม่มีวัตถุประสงค์ต้องไม่ถูกเก็บไว้)

## ความเสี่ยง

| ความเสี่ยง | รับมือ |
|---|---|
| ผู้สมัครพิมพ์อีเมลผิด → ผลสอบจับคู่กับใบสมัครไม่ได้ | ขั้นยืนยันอีเมลก่อนเริ่มสอบ (ชิ้นงาน 4) |
| record เก่าไม่มี `email` | นับก่อน migrate หยุดและรายงานถ้าเจอ |
| ผู้สมัคร 2 คนใช้อีเมลเดียวกัน → merge เป็นคนเดียว | ยอมรับ — ATS ก็ทำแบบนี้อยู่แล้ว พฤติกรรมจึงสอดคล้องกันขึ้น ไม่ใช่แย่ลง |
| DNS/ใบรับรองไม่พร้อมตอน cutover | ทดสอบ `assessment.hinomotorsasia.com` ให้ขึ้น HTTPS ปกติ **ก่อน** เปลี่ยน `index.html` เดิมเป็น redirect |
| ผู้สมัครที่กำลังทำข้อสอบค้างอยู่ตอนย้าย | หน้า redirect ทำให้เข้าถึงได้ต่อ แต่ progress ใน localStorage ผูกกับ origin เดิม — cutover ควรทำนอกเวลาที่มีคนสอบ |

## การทดสอบ

ต่อยอดจาก Playwright + pytest ที่มีอยู่ (`tests/conftest.py`)

1. ลงทะเบียนใหม่ → ไม่มีช่องเลขบัตร สอบจนจบ record ได้ `candidate_key` เป็นอีเมลตัวเล็ก
   และไม่มี `national_id` โผล่ที่ไหนเลย
2. โหลด fixture record เก่าที่มีแต่ `national_id` → ยังแสดงในตารางผู้สมัครได้ปกติ
3. กรอกอีเมลตัวพิมพ์ใหญ่ปน → key ที่บันทึกเป็นตัวพิมพ์เล็กเสมอ
4. ขั้นยืนยันอีเมล: กดย้อนกลับไปแก้อีเมลได้ และ key เปลี่ยนตาม
5. แผงยืนยันตัวตนแสดงก่อนฟอร์ม และลิงก์ `privacy.html` ต้องไม่ 404
6. ข้อความ consent ระบุครบทุกรายการที่ฟอร์มเก็บจริง (ทั้ง `th` และ `en`)
7. grep ทั้งไฟล์ → ไม่เหลือ `national_id` ในเส้นทางเขียนข้อมูล เหลือได้เฉพาะใน read-compat
8. หลัง deploy: `curl` ทุก path ที่ไม่ควร public บน domain ใหม่ ต้องได้ 404
   (`hma-ats.html`, `CONTEXT.md`, `README.md`, `hma-testing-system.html`)

## ต้องทำนอกโค้ด

1. **ขอ CNAME จาก IT** — กรอบข้อความ: ขอ DNS record ชี้ subdomain ไปที่ระบบทดสอบผู้สมัคร
   ของ HR ไม่ใช่คำขออนุมัติระบบ
2. สร้าง repo `assessment` เปิด Pages ผูก domain เปิด Enforce HTTPS
3. รันสคริปต์ migration บน Firestore (ต้องสิทธิ์ superadmin)
4. **ให้ชื่อ / อีเมล / เบอร์ HR ผู้รับผิดชอบ** — เป็น input ที่ขาดไม่ได้ของชิ้นงาน 2, 3, 5
   ถ้ายังไม่มีตอนเริ่ม implement ให้ใส่ค่า placeholder ที่เห็นชัดว่ายังไม่จริง และ
   **ห้าม cutover domain จนกว่าจะใส่ค่าจริงครบ**
5. หมุนรหัสผ่าน 3 ตัวเก่าที่ยังค้างจากรอบ audit ก่อนหน้า

## หนี้ที่บันทึกไว้ (นอกขอบเขต)

- เฉลยและการให้คะแนนยังอยู่ฝั่ง client — ผลสอบยังปลอมได้ ต้องมี server-side scoring
