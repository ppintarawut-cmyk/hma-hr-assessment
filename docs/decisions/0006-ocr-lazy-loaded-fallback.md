# OCR เป็นทางสำรอง โหลดเมื่อจำเป็น ไม่ใช่ทางหลัก

resume ที่ผู้สมัครสแกนหรือถ่ายรูปมาแปะใน PDF ไม่มีชั้นข้อความเลย (`getOperatorList()` คืน
`paintImageXObject` อย่างเดียว ไม่มี text operator) การ parse ทุกรูปแบบจึงได้ศูนย์ —
ทางเดียวคือ OCR ระบบใช้ tesseract.js (ไทย+อังกฤษ) โดยมีเงื่อนไขสามข้อ

**หนึ่ง — โหลดเมื่อจำเป็น** ไลบรารีกับชุดข้อมูลภาษารวมกันหลายสิบ MB ถ้าใส่เป็น `<script>`
ในหน้าเว็บ ทุกคนที่เปิดแอปจะต้องโหลดทั้งที่ส่วนใหญ่สแกนแต่ไฟล์ที่มีชั้นข้อความ จึงโหลด
ผ่าน `loadScriptOnce()` ตอนเจอไฟล์ที่ไม่มีข้อความจริง ๆ เท่านั้น (`OCR_MIN_CHARS`)

**สอง — เป็นทางสำรองเสมอ ไม่ใช่ทางหลัก** ไฟล์ที่มีชั้นข้อความจะไม่ถูก OCR แตะเลย
ข้อความจาก text layer แม่นกว่าและเร็วกว่าหลายสิบเท่า OCR ทำงานก็ต่อเมื่อ parse แล้วได้
ข้อความสั้นผิดปกติ

**สาม — ผลจาก OCR ถือว่า "ยังไม่ยืนยัน"** ทุกแถวที่มาจาก OCR ติดคำเตือนและ badge เสมอ
เพราะ OCR อ่านตัวอักษรเพี้ยนได้ (เคสจริง: จุดหน้า TLD หายไปกลายเป็น `uncharink@gmailcom`)
และการหาชื่อบนข้อความ OCR ถูกจำกัดให้ระวังกว่าปกติ — resume สองคอลัมน์ที่ OCR อ่านสลับ
ไปมาเคยให้ชื่อว่า "and shared" ซึ่งดูเหมือนคำตอบจริงทั้งที่เป็นเศษประโยค ตอนนี้ดูแค่
