# เก็บประวัติการเปลี่ยนสถานะผู้สมัคร — record เก่าไม่เดาวันที่

เดิม ATS รู้แค่สถานะปัจจุบันกับ `closedAt` จึงตอบไม่ได้ว่าผู้สมัครค้างอยู่ขั้นไหนนานเท่าไร
ใช้เวลากี่วันจนรับเข้าทำงาน หรือถูกคัดออกที่ขั้นไหน — และข้อมูลที่ไม่ได้เก็บไว้ตอนนี้ย้อนกลับมาไม่ได้
จึงเพิ่ม `candidate.stageHistory = [{ stage, at }]` ผ่าน `makeCandidate()` และต่อท้ายทุกครั้งที่ `setStage()`

record ที่สร้างก่อนมีฟีเจอร์นี้ (รวมไฟล์สำรองเก่า) สร้างประวัติจากเท่าที่รู้จริงตอนใช้งาน (`historyOf()`):
Applied ที่ `addedAt` + สถานะปัจจุบันที่ `closedAt` ถ้าเป็นสถานะปิด — นอกนั้นวันที่เป็น `null`
และทุก entry ติด `inferred: true` · สถิติระยะเวลาและจุดที่ถูกคัดออกนับเฉพาะการย้ายที่บันทึกจริง
(ไม่งั้น record เก่าที่ Rejected จะถูกนับว่าคัดออกตั้งแต่ Applied ทั้งหมด) ยกเว้นวันจนรับเข้าทำงาน
ซึ่งใช้ `closedAt` ของ Hired ได้เพราะถูกตั้งตอนเข้า Hired จริง

"ค้างสถานะ" = ยังไม่ปิดเคสและอยู่สถานะเดิมเกิน `STUCK_DAYS` (14 วัน) — แจ้งเตือนอย่างเดียว ไม่เปลี่ยนอะไรอัตโนมัติ
ประวัติอยู่บน record ผู้สมัคร จึงถูกลบไปพร้อมกันตามนโยบาย retention (decision 0004) และเข้า backup เอง

ทางเลือกที่ปัดตก: เดาวันที่เข้าสถานะของ record เก่า (ทำให้ค่าเฉลี่ยเพี้ยนแบบมองไม่เห็น),
เก็บ log แยกนอก record ผู้สมัคร (ต้องดูแลการลบตาม PDPA สองที่)
