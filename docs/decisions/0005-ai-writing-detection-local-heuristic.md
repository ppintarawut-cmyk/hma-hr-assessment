# ตรวจจับการใช้ AI เขียน resume ด้วย heuristic ในเครื่อง — เป็นสัญญาณประกอบ ไม่ใช่คำตัดสิน

HR ต้องการรู้ว่า resume ฉบับไหนใช้ AI ช่วยเขียน และใช้ในส่วนไหน (สรุปประวัติ / ประสบการณ์ / ทักษะ ฯลฯ)
จึงเพิ่มตัวตรวจ `detectAIWriting()` ใน hma-ats.html ที่ให้คะแนน "สัญญาณการใช้ AI" 0–100
รายบรรทัด → รายส่วน → ทั้งฉบับ จากสัญญาณที่อธิบายได้ทุกตัว:
ข้อความค้างจากแชตบอต, ร่องรอย citation ของ ChatGPT, placeholder ที่ยังไม่แทนค่า,
markdown ค้าง, emoji bullet, สำนวนที่ AI ใช้บ่อย (ไทย/อังกฤษ คิดตามความหนาแน่น) และ em dash ถี่

ทำงานในเครื่องทั้งหมด ไม่ส่ง resume ไปบริการตรวจ AI ภายนอก — ข้อมูลส่วนบุคคลผู้สมัครต้องไม่ออกนอกเครื่อง (decision 0001)
แลกกับความแม่นยำที่ต่ำกว่าโมเดลเฉพาะทาง จึงวางตัวเป็น "ข้อมูลประกอบ" เหมือนคะแนน Match:
ไม่มีผลกับคะแนน Match ไม่มีการคัดออกอัตโนมัติ และ UI บอกเสมอว่าไม่ใช่หลักฐานชี้ขาด
(การใช้ AI ช่วยเรียบเรียงไม่ได้แปลว่าข้อมูลเป็นเท็จ — ใช้เป็นจุดที่ควรถามยืนยันตอนสัมภาษณ์)

เก็บบน record แค่สรุปเล็ก ๆ `ai: { v, score, level, parts }` ผ่าน `makeCandidate()`
รายละเอียดรายบรรทัดคำนวณใหม่จาก `resumeText` ตอนเปิดดู (ไม่เก็บข้อความซ้ำ — quota localStorage)
record เก่า/ไฟล์สำรอง หรือสรุปจากกฎเวอร์ชันเก่า (`v` ≠ `AI_DETECT_VERSION`) คำนวณใหม่อัตโนมัติตอนใช้งาน

ทางเลือกที่ปัดตก: เรียก API ตรวจ AI ภายนอก (ขัด 0001), ให้คะแนน AI หักคะแนน Match (ลงโทษคนที่ใช้ AI
แค่ช่วยเรียบเรียงภาษา และ false positive กับคนที่เขียนภาษาทางการเอง), วัด "ความยาวประโยคสม่ำเสมอ"
(ลองแล้วจับ resume สั้น ๆ ที่คนเขียนเองผิดบ่อย)

## ส่วนเพิ่ม (2026-10-12): คำถามสัมภาษณ์จากส่วนที่พบสัญญาณ

ต่อยอดให้สัญญาณนำไปใช้ได้จริง: `aiInterviewQuestions()` สร้างคำถามจากบรรทัดที่พบสัญญาณ ด้วยเทมเพลตตาม "ธีม"
ของสำนวนที่พบ (ผลงาน / การปรับปรุง / การริเริ่ม / ข้อมูล / ทีม / ปัญหายาก / แรงจูงใจ / ทักษะ) —
บรรทัดในส่วนประสบการณ์ถามเจาะบรรทัดนั้นตรง ๆ และข้อความค้างจากแชตบอตได้คำถามกลาง ๆ 1 ข้อว่าเตรียม resume อย่างไร
ไม่ใช้ AI สร้างคำถาม (เหตุผลเดียวกับข้างบน) · HR ติ๊กเลือกแล้วใส่ลง "บันทึกย่อ" ของฟอร์มประเมินสัมภาษณ์
จึงถูกบันทึกไปกับใบประเมินโดยไม่ต้องเพิ่ม field ใหม่ · น้ำเสียงคำถามคือ "ขอตัวอย่างจริง" ไม่ใช่จับผิด
